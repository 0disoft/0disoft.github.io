## 把 Airtable 的数据连接做成订阅生意

安迪·克洛克（Andy Cloke）做的 Data Fetcher，是一个把外部服务的 API 数据抓进 Airtable 的扩展应用。2023 年 9 月 28 日公开的 Indie Bites 采访把它当作一个 MRR（月经常性收入）达到 2 万美元的生意来介绍。它解决的是 Airtable 使用者在抓取和刷新数据时的麻烦，长成了一个独立开发者能运营的订阅生意。

## 从上一个生意里找到下一个产品的线索

克洛克在牛津大学学的是工程，之后自学编程，在伦敦的几家创业公司做开发者。早期他做过西班牙语学习网站、足球竞猜应用等，但积累免费用户的经验并没有变成稳定收入。经过好几个项目，他学到的不只是开发，还有留住用户和变现的难处。

第一个赚到像样收入的产品，是帮人找 TikTok 网红的目录服务 Influence Grid。他把它做到 MRR 约 3,000 美元，然后在 2020 年中期以 5.5 万美元卖掉。出售所得成了开发下一个产品期间的生活费和服务器开销。

在找下一个点子的期间，他设想了一份介绍上市日程的邮件通讯。他想用 Airtable 管理内容，但股价这类金融数据很难方便地抓进来。他这时亲身碰到的麻烦，成了 Data Fetcher 的起点。

产品的形态，是在 Product Hunt 上看到的谷歌表格用 API Connector 那里具体起来的。克洛克用的办法是：把成熟平台上有需求验证过的工具，搬到另一个正在快速成长的平台上。Influence Grid 是把 Instagram 周边的生意机会用到 TikTok 上，Data Fetcher 则是把谷歌表格的 API 连接工具照 Airtable 的样子做出来。

## 在应用市场里遇到第一批客户

当时用 Zapier 或 Integromat 也能接外部数据。克洛克看重的差别，是不用离开 Airtable 就能设置并运行 API 请求这种便利。他做了把 API 响应里每一项对应到 Airtable 记录和字段格式的功能，抓来的数据可以直接放进正在编辑的表里。

真实需求并不限于某个行业。客户抓的有股价、汇率、加密货币价格和营销指标，也有把葡萄园在用的客户管理系统接进来的例子。2022 年采访当时，使用者接上的应用超过 1,000 个。一个通用的连接工具，同时承接了许多零碎的业务需求。

早期开发用上了他本来就熟的 React。第一版先做接 API 的核心功能，而应用市场的审核比开发还花时间。因为更新也要审批，所以他在上线前的测试和帮助文档上下了功夫。做平台内上架这门生意，连发布速度都要受外部流程影响。

早期的免费方案每月给 100 次执行，付费方案从每月 12 美元起。他把扩大的执行量和定时执行打包成付费功能，对反复刷新数据收费。当时 Airtable 应用市场没有支付功能，订阅是通过单独的网站和 Stripe 处理的。

2020 年 11 月 12 日他公布了 Airtable 应用市场上线，11 月 15 日公开了第一笔付费转化。到同年 12 月 15 日在 Product Hunt 上线时，已经有 300 多名使用者、10 位付费客户和累计 5,000 次以上的 API 请求。顺序是先看应用市场里的真实使用、把产品改好，再扩到更大的开发者社区。

## 反复使用和内容一起把订阅收入做大

早期增长很慢。MRR 在 600 美元左右停住之后，克洛克重新接起自由职业的活，利用晚上和周末开发产品。2021 年 6 月做到约 2,500 美元时，他把外包的日程调得更灵活，到年底把剩下的外包做完，转成了全职。

获客的中心是 Airtable 应用市场。在 2022 年的采访里，克洛克说大约 70~80% 的客户是通过这里发现产品的。他补强了上架页的功能说明和客户评价，又加上 Google 登录来减少注册过程中的麻烦。他还说，当时从免费试用到付费客户的转化率大约是 10%。

在应用市场之外，他做了解释客户具体工作的博客和 YouTube 内容。选题挑的是“怎么把股价或 Google Maps 数据抓进 Airtable”这类要解决的问题很明确的题目。克洛克公开过一条播放量约 1,000 次的视频带来 30 多名付费客户的例子，说明播放量不大，也能碰到购买意愿很强的人。

产品的使用范围也从懂 API 的早期客户，扩到了非开发者。常用的服务提供预先配置好的连接功能，有技术基础的使用者则可以用 Custom requests 自己接 REST、GraphQL API。基本的连接容易上手，同时又保住了能把清单里没有的服务也接进来的灵活性。

2022 年 3 月的采访里，他公开了 190 位付费客户和 6,500 美元的 MRR，同年 9 月宣布 MRR 达到 1 万美元。3 月时服务器和办公工具的费用是每月约 500 美元，克洛克说除去自己那份薪水，利润率约为 90%。这个数字还没有扣掉创始人自己的劳动报酬，把这一点也算进来，才能准确理解这门生意的盈利能力。

运营积累得越久，处理异常数据也成了重要的资产。他得修真实客户带来的问题，比如很大的响应文件或格式不正常的 CSV，而定时执行失败有时会直接导致客户取消。克洛克认为，这样攒下来的错误处理经验，是竞争对手不容易追上的部分。

## 应对增长停滞和对平台的依赖

即便 MRR 到了 2 万美元，增长停滞还是找上门来。克洛克说，从 2023 年 8 月起大约五个月里，新订阅和取消相互抵消，流失率停在 10~11%。12 月他给年付方案加上 50% 的折扣，并把价格页面的默认选项改成按年付款。之后他报告说流失率降到 7%，MRR 也重新涨了起来。

在 2024 年的后续采访里，他公开了 2.3 万美元的 MRR。全职运营的只有克洛克一个人，但视频制作和开发上用了兼职的协作者。他保持小规模运营，同时把需要的专业工作交给外面。

想把别的产品卖给现有客户的尝试，成果很小。他用同一品牌推出的 Airtable 可视化扩展应用 Charts & Reports，大约一年里都停在 MRR 300 美元。克洛克把这件事评为一个上得太早的第二个产品，也分散了注意力。

对平台的依赖也变成了现实的风险。克洛克说，Airtable 把扩展应用从免费方案里排除、改变价格政策之后，Data Fetcher 的新注册就少了。Airtable API 的限制变动他也得跟着应对。给自己供给客户的平台，同时也决定了客户的可达性和产品的运营条件。

Data Fetcher 在生意上的意义，在于它盯住了已经选好办公工具的人反复碰到的小麻烦。它在应用市场里遇到客户，用讲清具体用法的内容带来更多流量，又对数据刷新持续收费，把这条链条搭了起来。这个案例既说明平台内一个很窄的功能也能成为独立的生意，也显出维持稳定连接和反复使用的运营能力有多重要。
