## Airtable의 데이터 연결을 구독 사업으로 만들다

앤디 클로크(Andy Cloke)가 만든 Data Fetcher는 외부 서비스의 API 데이터를 Airtable로 가져오는 확장 앱이다. 2023년 9월 28일 공개된 Indie Bites 인터뷰에서 월 반복매출(MRR) 2만 달러를 기록한 사업으로 소개됐다. Airtable을 사용하는 사람들이 데이터 수집과 갱신에서 겪는 불편을 해결하면서, 독립 개발자가 운영할 수 있는 구독 사업으로 성장했다.

## 앞선 사업에서 다음 제품의 실마리를 찾다

클로크는 옥스퍼드대학교에서 공학을 공부한 뒤 프로그래밍을 독학했고, 런던의 스타트업들에서 개발자로 일했다. 초기에는 스페인어 학습 사이트와 축구 퀴즈 앱 등을 만들었지만, 무료 이용자를 확보하는 경험이 안정적인 수입으로 이어지지는 않았다. 여러 프로젝트를 거치며 개발뿐 아니라 사용자 유지와 수익화의 어려움을 배웠다.

처음 의미 있는 수익을 낸 제품은 틱톡 인플루언서를 찾는 디렉터리 서비스 Influence Grid였다. 그는 이 서비스를 MRR 약 3,000달러까지 키운 뒤, 2020년 중반 5만 5,000달러에 매각했다. 매각 대금은 다음 제품을 개발하는 동안 생활비와 서버 비용을 감당하는 자금이 됐다.

다음 아이디어를 찾던 중에는 기업공개 일정을 소개하는 뉴스레터를 구상했다. 콘텐츠를 Airtable로 관리하려 했지만, 주가 같은 금융 데이터를 간편하게 가져오기 어려웠다. 이때 직접 겪은 불편이 Data Fetcher의 출발점이 됐다.

제품의 형태는 Product Hunt에서 발견한 구글 스프레드시트용 API Connector에서 구체화됐다. 클로크는 성숙한 플랫폼에서 수요가 확인된 도구를 빠르게 성장하는 다른 플랫폼에 맞춰 제공하는 방식을 활용했다. Influence Grid에서는 인스타그램 주변의 사업 기회를 틱톡에 적용했고, Data Fetcher에서는 구글 스프레드시트의 API 연결 도구를 Airtable에 맞게 구현했다.

## 마켓플레이스에서 첫 고객을 만나다

당시에도 Zapier나 Integromat를 이용하면 외부 데이터를 연결할 수 있었다. 클로크가 주목한 차이는 Airtable을 떠나지 않고 API 요청을 설정하고 실행하는 편의성이었다. API 응답의 각 항목을 Airtable의 레코드와 필드 형식에 대응시키는 기능을 갖춰, 가져온 데이터를 작업 중인 표에 바로 넣을 수 있도록 했다.

실제 수요는 특정 업종에 한정되지 않았다. 고객들은 주가·환율·암호화폐 가격과 마케팅 지표를 가져왔고, 포도원에서 사용하는 고객관리 시스템을 연결한 사례도 있었다. 2022년 인터뷰 당시 이용자들이 연결한 애플리케이션은 1,000개가 넘었다. 하나의 범용 연결 도구가 여러 작은 업무 수요를 함께 수용하는 구조였다.

초기 개발에는 기존에 익숙했던 React 경험을 활용했다. 첫 버전은 API에 연결하는 핵심 기능부터 구현했으며, 개발보다 마켓플레이스 심사에 더 오랜 시간이 걸렸다. 업데이트에도 승인이 필요했기 때문에 출시 전 테스트와 도움말 문서에 공을 들였다. 플랫폼에 입점하는 사업에서는 배포 속도까지 외부 절차의 영향을 받았다.

초기 무료 요금제는 월 100회 실행을 제공했고, 유료 요금제는 월 12달러부터 시작했다. 실행량 확대와 예약 실행을 유료 기능으로 묶어 반복적인 데이터 갱신에 과금했다. 당시 Airtable 마켓플레이스에는 결제 기능이 없어, 별도 웹사이트와 Stripe로 구독을 처리했다.

2020년 11월 12일에는 Airtable 마켓플레이스 출시를 알렸고, 11월 15일에는 첫 유료 전환 소식을 공개했다. 같은 해 12월 15일 Product Hunt에 출시할 무렵에는 이용자 300명 이상, 유료 고객 10명, 누적 API 요청 5,000회 이상을 기록했다. 마켓플레이스에서 실제 사용을 확인하고 제품을 개선한 뒤, 더 넓은 개발자 커뮤니티로 공개 범위를 늘린 순서였다.

## 반복 사용과 콘텐츠가 구독 매출을 키우다

초기 성장은 더뎠다. MRR이 약 600달러에서 정체되자 클로크는 프리랜서 일을 다시 시작하고 밤과 주말에 제품을 개발했다. 2021년 6월 약 2,500달러에 도달하면서 외주 일정을 유연하게 조정했고, 연말에 남은 외주를 마무리하며 전업으로 전환했다.

고객 확보의 중심은 Airtable 마켓플레이스였다. 2022년 인터뷰에서 클로크는 고객의 약 70~80%가 이곳을 통해 제품을 발견한다고 설명했다. 그는 입점 페이지의 기능 설명과 고객 후기를 보강하고, Google 로그인을 추가해 가입 과정의 불편을 줄였다. 무료 체험에서 유료 고객으로 전환되는 비율도 당시 약 10%라고 밝혔다.

마켓플레이스 밖에서는 고객의 구체적인 작업을 설명하는 블로그와 유튜브 콘텐츠를 만들었다. 주가나 Google Maps 데이터를 Airtable로 가져오는 방법처럼 해결하려는 문제가 분명한 주제를 골랐다. 클로크는 조회수 약 1,000회의 영상에서 유료 고객 30명 이상을 확보한 사례를 공개했으며, 적은 조회수에서도 구매 의도가 높은 이용자를 만날 수 있었다.

제품도 API를 이해하는 초기 고객층에서 비개발자로 사용 범위를 넓혔다. 자주 쓰는 서비스에는 미리 구성된 연결 기능을 제공하고, 기술 지식이 있는 이용자는 Custom requests로 REST·GraphQL API를 직접 다룰 수 있도록 했다. 기본 연결은 쉽게 시작하면서도, 준비된 목록에 없는 서비스까지 연결할 수 있는 유연성을 유지했다.

2022년 3월 인터뷰에서는 유료 고객 190명과 MRR 6,500달러를 공개했고, 같은 해 9월에는 MRR 1만 달러 도달을 알렸다. 3월 당시 서버와 업무 도구 비용은 월 약 500달러였으며, 클로크는 자신의 급여를 제외한 이익률을 약 90%로 설명했다. 창업자의 노동 대가를 아직 차감하지 않은 수치라는 점까지 포함해야 이 사업의 수익성을 정확히 이해할 수 있다.

운영이 쌓일수록 예외적인 데이터 처리도 중요한 자산이 됐다. 큰 응답 파일이나 비정상적인 CSV 형식처럼 실제 고객이 가져오는 문제들을 고쳐야 했고, 예약 실행 실패는 해지로 이어지기도 했다. 클로크는 이렇게 누적한 오류 처리 경험을 경쟁자가 쉽게 따라 하기 어려운 부분으로 봤다.

## 정체와 플랫폼 의존을 관리하다

MRR 2만 달러에 이른 뒤에도 성장 정체는 찾아왔다. 클로크는 2023년 8월부터 약 5개월 동안 신규 구독과 해지가 상쇄됐고, 이탈률이 10~11%에 머물렀다고 밝혔다. 12월에는 연간 요금제에 50% 할인 혜택을 적용하고 가격 페이지의 기본 선택을 연간 결제로 바꿨다. 이후 이탈률이 7%로 낮아지고 MRR이 다시 증가했다고 보고했다.

2024년 후속 인터뷰에서는 MRR 2만 3,000달러를 공개했다. 전업 운영자는 클로크 한 명이었지만, 영상 제작과 개발에는 시간제 협력자를 활용했다. 작은 운영 규모를 유지하면서 필요한 전문 작업을 외부에 맡겼다.

기존 고객에게 다른 제품을 판매하려던 시도는 성과가 작았다. 같은 브랜드로 출시한 Airtable 시각화 확장 앱 Charts & Reports는 약 1년 동안 MRR 300달러에 머물렀다. 클로크는 이를 너무 일찍 출시한 두 번째 제품이자 집중력을 분산시키는 일로 평가했다.

플랫폼 의존성도 현실적인 위험으로 나타났다. 클로크는 Airtable이 무료 요금제에서 확장 앱을 제외하고 가격 정책을 바꾼 뒤 Data Fetcher의 신규 가입이 줄었다고 설명했다. Airtable API의 제한 변경에도 대응해야 했다. 고객을 공급해 주는 플랫폼이 동시에 고객 접근성과 제품 운영 조건을 결정했다.

Data Fetcher의 사업적 의미는 이미 업무 도구를 선택한 사람들이 반복해서 겪는 작은 불편에 집중했다는 데 있다. 마켓플레이스에서 고객을 만나고, 구체적인 사용법 콘텐츠로 추가 유입을 만들며, 데이터 갱신에 지속적으로 과금하는 흐름을 구축했다. 이 사례는 플랫폼 안의 좁은 기능도 독립적인 사업이 될 수 있음을 보여 주면서, 안정적인 연결과 반복 사용을 유지하는 운영 역량의 중요성을 함께 드러낸다.
