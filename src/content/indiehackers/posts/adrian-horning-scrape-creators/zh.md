## 把社交平台数据抓取当成开发者 API 来卖

阿德里安·霍宁(Adrian Horning)做了一个面向开发者的社交平台数据抓取 API，名叫 Scrape Creators。2024 年 6 月他正式着手推进这门生意，一年后在 2025 年 7 月 31 日公开的 Indie Hackers 采访中，他说月销售额已经超过 1 万美元。

## 学会技术，为独立做准备

他在大学读的是心理学。实习期间接触到优步(Uber)，由此对科技行业产生兴趣，于是搬到旧金山读了编程训练营。那段时间他在 Lyft 打工、骑自行车送外卖来维持生活，之后在犹他州做了大约三年软件工程师。

2022 年辞职时，他账户里有 3 万美元，还有一个小应用每月进账 500 美元。但独立之后，他几次差点把资金花光，靠接自由职业和卖爬虫课程撑了下来。在产品能负担生活费之前，是这些外部收入为他保住了开发时间。

早期的实验里有一个叫 Auto Apply 的东西，能在领英上找到招聘负责人并自动发邮件。当时它依赖用 Puppeteer 自动操作浏览器，经常被封、抓取也不稳定，让他吃了不少苦头。

技术上的转折点来自朋友杰克的一个请求。杰克想请他在妻子想要的 Lululemon 衣服重新到货时发短信提醒，于是他开始研究网站内部调用的 API。他在浏览器开发者工具里找到那些数据请求，学会了直接拿到 JSON 响应，后来做自由职业和课程时都用上了这段经验。

## 把已有的代码打包成能卖的 API

决定商业模式时，一则别家公司的出售公告影响了他。有位关注者把 MicroAcquire 上挂出的一桩社交平台抓取 API 生意发给他，他由此确认：类似功能已经有市场愿意付钱。他判断，可以把散落在多个项目里的抓取功能打包起来出售。

一开始，他把 TikTok 创作者数据库和抓取 API 一起做了大约半年。创作者数据库的维护成本高、运营负担重，而 API 赚钱的可能性看起来更明确。最终他收掉了数据库这块生意，选择把精力集中到 API 上。

Scrape Creators 的基本功能，是抓取公开的个人资料、帖子、评论、视频信息等，以 JSON 形式返回。客户把这些数据接进自己的程序，而服务方负责管理各平台的抓取方式以及故障处理。YouTube、TikTok 视频的字幕文稿和广告库数据，也被纳入了重要的产品范围。

客户群包括做社交平台分析工具的开发者、营销代理公司、研究者和内容创作者等。比如，代理公司可以对比竞争对手的广告，开发者可以做汇集多个平台数据的看板。视频文稿则被用来二次加工内容，或者做成可检索的资料库。

实际用量也反映出需求的性质。霍宁在 2025 年 9 月公布的自家统计里，Instagram 个人资料查询有 431 万次，TikTok 视频文稿请求有 382 万次。从这组数据看，查看账号规模和基本信息、分析视频内容，这两类操作都是主要的使用场景。

## 按用量出售的积分

付费方式是先按需购买积分，再用积分来调用 API。采访里用了 MRR 这个说法，但这个数字要放在“按用量计费的积分产品的月销售额”这个语境里理解。它和每月固定收费的订阅在收入性质上并不一样，在这种结构里，持续抓取数据的客户不断复购才是关键。

2026 年 9 月查看的官方价目表上，列着一口价购买的产品：2.5 万积分 47 美元，50 万积分 497 美元。大多数功能调用一次消耗 1 积分，但有些功能需要更多积分。新用户可以先用赠送的 100 免费积分，试一下返回的数据和运行方式。

## 主动去找客户，并专注一个产品

第一个客户来自技术内容。霍宁在推特上公开了抓取某家公司网站的方法，那家公司的首席技术官看到后回应，并问起了他的 API。一条展示工作过程的帖子证明了他的技术能力，也直接带来了真实交易。

之后，他会去找看起来需要社交平台数据的产品，主动联系人。看到别的创业者的宣传视频或帖子，他就提出赠送 1 万免费积分让对方试用 API，靠这个办法拿下了客户。消息都是他亲自发的，没有依赖大批量的自动化销售。

他把 X 的私信和谷歌搜索列为主要获客渠道。靠免费内容积累的声誉帮上了忙，不过他并没有精确追踪各渠道表现的那套运营方式。

他还做了用来展示产品的免费工具。发在领英上的 YouTube Comment Analyzer，输入视频地址就能分析评论，用的正是他自己做的 YouTube 评论抓取 API。这是一个让用户直接看到 API 能做出什么成果的例子。

增长上的重要变化，出现在他减少花在其他事情上的时间之后。过去他同时做多个项目和自由职业委托，后来集中到 Scrape Creators 上，熬过艰难的几个月后，2025 年 3 月已经能覆盖大部分生活费。那年夏天，月销售额超过了 1 万美元。

客户响应是他强调的竞争打法。客户 Gil Hildebrand 在采访评论里评价说，霍宁几乎有问即答，还会提供自己需要的功能。霍宁也说过，在 API 这门生意里，创始人是否容易联系上、支持是否及时，本身就是竞争力。

## 把维护也算进去的小型基础设施生意

根据 2025 年 9 月公开的技术说明，核心服务器用的是 Node.js 和 Express，用 Redis 处理积分状态和缓存。能做的操作尽量用直接的 HTTP 请求完成，只有在 TikTok Shop 这类功能确实需要时才动用浏览器。也就是说，他优先选择了能让一个人自己排查并修好问题的简单结构。

运营上负担最重的部分，是代理 IP 的质量和各平台抓取的稳定性。为了减少可靠性问题，他换掉了代理服务商，并说明了自己按功能查看成功率、响应时间和错误规律的做法。对客户来说只是一次简单调用的服务，背后也要持续投入维护成本。

依赖外部平台的风险始终存在。Scrape Creators 的服务条款写明：外部网站的改动或自动访问封禁都可能导致功能中断，而遵守相关网站条款和隐私法规的责任在使用者身上。即便是去买一个提供公开数据的 API，使用前也仍有必要确认数据抓取和使用的条件。

拓宽使用门槛的工作也在继续。2025 年 9 月他推出了一个 n8n 专用节点，不用手写复杂的 HTTP 请求就能使用，如今在 n8n 官方集成列表里也能查到它是经过验证的节点。这是把开发者做的抓取功能，延伸到使用工作流自动化工具的那批人身上。

2026 年 9 月查看的官方介绍页面上，团队规模显示为 3 人。它从 2025 年一个人的开发产品，扩展成了小团队运营，而“不接受外部投资”的说明一直保留着。

Scrape Creators 是靠复用多次实验里攒下的抓取代码、再直接卖给需要这些数据的开发者，这样长起来的。霍宁卖出去的价值，在于让客户轻松拿到想要的数据，并且在抓取方式变化时持续替他们修好。
