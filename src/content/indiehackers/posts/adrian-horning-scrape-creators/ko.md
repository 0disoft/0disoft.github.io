## 수집 코드를 판매 가능한 API로 만들다

에이드리언 호닝(Adrian Horning)은 소셜미디어 데이터를 수집하는 개발자용 API인 스크레이프 크리에이터스(Scrape Creators)를 만들었다. 2024년 6월 이 사업을 본격적으로 추진한 뒤, 2025년 7월 31일 공개된 Indie Hackers 인터뷰에서 약 1년 만에 월매출 1만 달러를 넘겼다고 밝혔다.

## 기술을 익히고 독립을 준비하다

대학에서는 심리학을 전공했다. 인턴 시절 우버를 접하면서 기술 업계에 관심을 가졌고, 샌프란시스코로 옮겨 코딩 부트캠프에 다녔다. 그동안 리프트에서 일하고 자전거로 음식을 배달하며 생활비를 마련했으며, 이후 유타에서 소프트웨어 엔지니어로 약 3년간 일했다.

2022년 퇴사 당시 통장에는 3만 달러가 있었고, 작은 앱 하나에서 월 500달러가 들어오고 있었다. 그러나 독립 후 몇 차례 자금이 바닥날 상황을 겪었으며, 프리랜서 작업과 스크래핑 강의 판매로 버텼다. 제품이 생활비를 감당하기까지 외부 수입이 개발 시간을 확보해 주었다.

초기 실험 중에는 링크드인에서 채용 담당자를 찾아 이메일을 보내는 ‘Auto Apply’가 있었다. 당시에는 브라우저를 자동 조작하는 Puppeteer에 의존했고, 잦은 차단과 불안정한 수집 때문에 어려움을 겪었다.

기술적 전환점은 친구 제이크의 부탁이었다. 아내가 사고 싶어 하는 룰루레몬 의류의 재입고를 문자로 알려 달라는 요청을 받고, 웹사이트가 내부적으로 호출하는 API를 살펴보기 시작했다. 브라우저 개발자 도구에서 데이터 요청을 찾아 JSON 응답을 직접 받는 방법을 익혔고, 이후 프리랜서 작업과 강의에도 이 경험을 활용했다.

## 기존 코드를 판매 가능한 API로 묶다

사업 형태를 정하는 데에는 다른 회사의 매각 공고가 영향을 주었다. 한 팔로어가 MicroAcquire에 올라온 소셜미디어 스크래핑 API 사업을 보내 주었고, 그는 비슷한 기능에 이미 돈을 내는 시장이 있음을 확인했다. 여러 프로젝트에서 만들어 둔 수집 기능을 묶어 판매할 수 있겠다고 판단했다.

처음에는 틱톡 크리에이터 데이터베이스와 스크래핑 API를 약 6개월간 함께 운영했다. 크리에이터 데이터베이스는 유지 비용과 운영 부담이 컸고, API에서는 수익을 낼 가능성이 더 뚜렷하게 보였다. 그는 데이터베이스 사업을 정리하고 API에 집중하는 방향을 택했다.

Scrape Creators의 기본 기능은 공개 프로필, 게시물, 댓글, 영상 정보 등을 수집해 JSON 형태로 돌려주는 것이다. 고객은 이 데이터를 자신의 프로그램에 연결하고, 서비스 운영자는 플랫폼별 수집 방식과 장애 대응을 관리한다. 유튜브·틱톡 영상의 대본과 광고 라이브러리 데이터도 중요한 상품 범위에 포함됐다.

고객군은 소셜미디어 분석 도구를 만드는 개발자, 마케팅 대행사, 연구자, 콘텐츠 제작자 등이다. 예를 들어 대행사는 경쟁사의 광고를 비교하고, 개발자는 여러 플랫폼의 수치를 모으는 대시보드를 만들 수 있다. 영상 대본은 콘텐츠 재가공이나 검색 가능한 자료실을 만드는 데 쓰인다.

실제 사용량에서도 수요의 성격이 드러났다. 호닝이 2025년 9월 공개한 자체 집계에서 인스타그램 프로필 조회는 431만 회, 틱톡 영상 대본 요청은 382만 회였다. 이 자료에서는 계정의 규모와 기본 정보를 확인하는 작업, 영상 내용을 분석하는 작업이 모두 주요 사용처로 나타났다.

## 사용량에 맞춰 판매하는 크레딧

결제는 필요한 만큼 크레딧을 먼저 구매하고 API 호출에 사용하는 방식이다. 인터뷰는 MRR이라는 표현을 사용했지만, 이 수치는 사용량 기반 크레딧 상품의 월매출이라는 맥락으로 읽을 필요가 있다. 매달 동일한 금액을 청구하는 구독과는 수입의 성격이 다르며, 데이터 수집을 계속하는 고객의 반복 구매가 중요해지는 구조다.

2026년 9월 확인한 공식 가격표에는 2만 5,000크레딧에 47달러, 50만 크레딧에 497달러인 일회성 구매 상품이 제시돼 있다. 대부분의 기능은 호출 한 번에 1크레딧을 쓰지만, 일부 기능은 더 많은 크레딧을 요구한다. 처음에는 무료 100크레딧으로 응답 데이터와 작동 방식을 시험할 수 있다.

## 고객을 찾아가고 한 제품에 집중하다

첫 고객은 기술 콘텐츠에서 나왔다. 호닝이 어느 회사의 웹사이트를 스크래핑하는 방법을 트위터에 공개하자, 그 회사의 최고기술책임자가 반응하고 그의 API에 관해 물었다. 작업 과정을 보여 준 게시물이 기술 역량을 증명하면서 실제 거래로 이어졌다.

이후에는 소셜미디어 데이터가 필요해 보이는 제품을 찾아 직접 연락했다. 다른 창업자의 홍보 영상이나 게시물을 보고 API를 시험할 무료 1만 크레딧을 제안했고, 이 방식으로 고객을 확보했다. 메시지 발송은 직접 했으며, 대량 자동화 영업에 의존하지 않았다.

그는 주요 유입 경로로 X의 개인 메시지와 구글 검색을 꼽았다. 무료 콘텐츠로 쌓은 평판이 도움이 됐지만, 채널별 성과를 정밀하게 추적하는 운영 방식은 아니었다.

제품을 보여 주는 무료 도구도 만들었다. 링크드인에 공개한 ‘YouTube Comment Analyzer’는 영상 주소를 넣으면 댓글을 분석하는 도구로, 자신이 만든 유튜브 댓글 수집 API를 활용했다. API가 어떤 결과물을 가능하게 하는지 사용자가 직접 확인할 수 있는 사례였다.

성장의 중요한 변화는 다른 일에 쓰던 시간을 줄인 뒤에 찾아왔다. 여러 프로젝트와 프리랜서 의뢰를 병행하다 Scrape Creators에 집중했고, 어려운 몇 달을 지나 2025년 3월에는 생활비 대부분을 충당하게 됐다. 그해 여름 월매출 1만 달러를 넘겼다.

고객 대응은 그가 강조한 경쟁 방식이었다. 고객인 길 힐데브랜드(Gil Hildebrand)는 인터뷰 댓글에서 호닝이 거의 즉시 답하고 자신에게 필요한 기능을 제공한다고 평가했다. 호닝 역시 API 사업에서는 연락하기 쉬운 창업자와 빠른 지원이 경쟁력이 된다고 설명했다.

## 유지보수까지 포함하는 작은 인프라 사업

2025년 9월 공개한 기술 설명에 따르면 핵심 서버는 Node.js와 Express를 사용했고, Redis로 크레딧 상태와 캐시를 처리했다. 가능한 작업은 직접 HTTP 요청으로 수행하고, 브라우저 실행은 일부 틱톡 숍 기능처럼 필요한 경우에 제한했다. 혼자 문제를 추적하고 고칠 수 있는 단순한 구성을 우선한 셈이다.

운영 부담이 큰 부분은 프록시 품질과 플랫폼별 수집 안정성이었다. 그는 신뢰성 문제를 줄이기 위해 프록시 공급자를 바꾸었고, 기능별 성공률과 응답 시간, 오류 패턴을 살피는 운영을 설명했다. 고객에게는 간단한 호출 한 번으로 보이는 서비스에도 지속적인 유지보수 비용이 들어간다.

외부 플랫폼에 의존한다는 위험도 남는다. Scrape Creators의 이용약관은 외부 사이트의 변경이나 자동 접근 차단으로 기능이 중단될 수 있다고 명시하며, 해당 사이트의 약관과 개인정보 관련 법률을 준수할 책임을 이용자에게 둔다. 공개 데이터를 제공하는 API를 구매해도 데이터의 수집·활용 조건을 검토할 필요는 남아 있다.

접근성을 넓히는 작업도 이어졌다. 2025년 9월에는 n8n에서 복잡한 HTTP 요청을 직접 작성하지 않고 사용할 수 있는 전용 노드를 소개했고, 현재 n8n 공식 통합 목록에서도 검증된 노드로 확인된다. 개발자가 만든 수집 기능을 업무 자동화 도구 사용자에게까지 연결한 확장이었다.

2026년 9월 확인한 공식 소개 페이지에는 팀 규모가 3명으로 표시돼 있다. 2025년의 1인 개발 제품에서 소규모 팀 운영으로 확대됐으며, 외부 투자 없이 운영한다는 설명은 유지되고 있다.

Scrape Creators는 여러 실험에서 쌓인 수집 코드를 재사용하고, 그 데이터가 필요한 개발자에게 직접 판매하면서 성장했다. 호닝이 판매한 가치는 원하는 데이터를 쉽게 가져오게 해 주고, 수집 방식이 바뀌었을 때 계속 고쳐 주는 서비스에 있었다.
