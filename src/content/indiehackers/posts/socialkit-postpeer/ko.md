## 익숙한 기술로 다시 시작하다

조너선 가이거(Jonathan Geiger)는 작은 스타트업에서 개발자로 일하면서 밤과 주말에 개인 제품을 만들었다. 3년간 이어진 부업에서 그가 자리 잡은 분야는 데이터 수집과 업무 자동화를 위한 API, 곧 다른 프로그램이 가져다 쓰는 기능이었다. SocialKit은 소셜미디어의 데이터를 꺼내 주고, PostPeer는 여러 소셜미디어에 콘텐츠를 올려 주는 사업으로 성장했다.

앞서 그는 학습 관리 도구 LectureKit과 웹페이지 캡처·수집 API인 CaptureKit을 만들어 매각했다. SocialKit 개발에는 CaptureKit의 로그인과 결제, API 키 관리, 문서 구성과 소개 페이지의 틀을 재사용했다. 덕분에 새 제품에서는 소셜미디어 데이터를 처리하는 고유 기능에 집중할 수 있었다.

제품을 고르는 기준도 달라졌다. 가이거는 자신이 이해하는 분야에서 이미 매출을 올리는 경쟁 제품을 찾았고, 빠른 지원처럼 직접 개선할 수 있는 부분을 공략했다. 개발자가 어떤 연동 작업을 번거로워하는지 아는 경험이 이 선택을 뒷받침했다.

## 소셜미디어 데이터를 공통 API로 제공하다

SocialKit이 다루는 문제는 소셜미디어의 콘텐츠를 다른 프로그램에서 활용할 때 생긴다. 동영상을 분석하려면 영상 정보와 대본을 확보하고, 필요에 따라 댓글이나 반응 지표를 수집하며, 요약 모델까지 연결해야 한다. SocialKit은 이런 작업을 묶어 동영상 주소와 요청을 보내면 필요한 결과를 돌려주도록 만들었다. 고객은 플랫폼별 수집 도구와 전사 서비스, 인공지능 모델을 각각 연결하는 수고를 줄일 수 있었다.

결과를 프로그램이 읽기 쉬운 JSON 형식으로 제공한 것도 중요했다. 고객은 대본과 댓글을 분석 서비스에 넣거나, 조회 수와 채널 정보를 보고서·대시보드에 옮기는 식으로 자기 제품에 결합할 수 있다. 가령 여러 채널의 반응을 비교하는 서비스를 만든다면, 데이터 수집은 SocialKit에 맡기고 비교 기준과 화면 구성에 개발 시간을 쓸 수 있다. 이렇게 고객마다 다른 완성품에 들어가는 공통 기능을 판매했다.

결제 전에는 실제 작업을 시험할 수 있게 했다. SocialKit과 PostPeer 모두 테스트용 20크레딧을 제공하고, 유료 이용은 사용량에 따른 구독과 일회성 크레딧 구매로 나눴다. 정기적으로 작업을 실행하는 고객과 필요할 때만 데이터를 가져오는 고객을 함께 받을 수 있는 구조다. 무료 체험의 역할도 자신의 데이터와 작업에 API가 맞는지 확인하는 데 분명하게 놓여 있었다.

## 검색에서 실제 고객을 만나다

고객을 찾는 작업은 개발과 함께 진행했다. 가이거는 매주 한두 편의 관련 글을 쓰고, API 기능별 소개 페이지와 사용 사례, 경쟁 서비스의 대안을 찾는 사람을 위한 비교 페이지를 만들었다. 고객이 검색할 표현으로 직접 검색한 뒤, 그 질문에 답하는 문서와 사용법을 채워 나갔다. 그가 공개한 성장 회고에서 검색을 통한 자연 유입은 가장 중요한 고객 유입 경로였다.

무료 유튜브 대본 추출기는 유료 API로 들어오는 입구가 됐다. 검색으로 도구를 발견한 사람 중 일부가 유료 고객으로 전환됐고, 사용법 콘텐츠는 글과 영상으로 함께 제작했다. 같은 내용을 짧은 영상과 소셜미디어 게시물로 다시 활용하면서 한 번 만든 자료가 여러 곳에서 발견되도록 했다. 경쟁 제품과 비교한 페이지를 인공지능 검색·추천 서비스에서 접하고 결제한 고객도 있었다.

실제로 돈을 낸 사람들은 가이거가 처음 상정한 개발자 집단보다 넓었다. 유료 고객의 상당 부분은 코드를 직접 작성하지 않고 노코드 도구로 업무를 연결하는 사람들이었다. SocialKit은 Zapier나 Make 같은 자동화 도구에서도 사용할 수 있었으므로, API 사용법을 익힌 개발자 외에도 반복적인 콘텐츠 수집 업무를 가진 사람들에게 접근할 수 있었다. 이 경험은 고객을 직업명보다 수행하려는 작업으로 이해해야 한다는 점을 보여 준다.

## 게시 작업과 플랫폼 비용을 묶다

2026년 4월에 출시한 PostPeer는 소셜미디어에 콘텐츠를 보내는 작업을 맡았다. 여러 플랫폼에 게시하고 예약하는 기능을 하나의 API로 제공해, 고객이 자기 서비스 안에 소셜미디어 게시 기능을 붙일 수 있도록 했다. SocialKit이 분석과 재가공에 필요한 자료를 공급했다면, PostPeer는 만들어진 콘텐츠를 배포하는 단계에 자리 잡았다.

PostPeer를 사용하는 서비스는 먼저 계정 소유자의 동의를 받아 소셜 계정을 연결한다. 이후 게시할 내용과 대상 계정을 전달하고, 즉시 발행하거나 시간대와 시각을 지정해 예약할 수 있다. 고객별로 연결된 계정을 묶는 기능도 제공하므로 여러 회사의 계정을 관리하는 대행사나 다수 사용자를 가진 서비스에 넣기 좋다. 플랫폼별 계정 연결과 게시 절차를 공통된 사용 방식으로 정리한 것이 제품의 핵심이었다.

PostPeer는 처음부터 파트너와 함께 개발했다. 두 사람은 플랫폼 연동을 나누어 맡았고, 가이거가 SocialKit에 집중하는 동안에도 개발을 이어갈 수 있었다. 특히 틱톡의 승인 절차는 예상보다 많은 수고를 요구했다.

사용량을 크레딧으로 환산하는 방식에는 플랫폼마다 다른 비용도 반영했다. PostPeer의 2026년 9월 요금표에서 대부분의 플랫폼은 게시물 한 건당 1크레딧을 차감하지만, X는 본문에 링크가 없으면 5크레딧, 있으면 50크레딧을 차감한다. 회사는 이 차이가 X에 지급하는 요청 비용에서 비롯된다고 설명한다. 고객에게는 하나의 API를 제공하면서도, 내부에서 발생하는 비용 차이는 과금 단위에 남겨 둔 셈이다.

고객 지원도 구매자가 체감하는 차이를 만드는 요소였다. PostPeer의 가격 페이지에는 빠른 응답과 수정 속도를 언급하는 후기가 배치돼 있으며, Kalizzle AI Studio의 창업자는 가이거가 몇 시간 안에 수정 사항을 반영했다고 평가했다. 외부 API 연결에서 문제가 생기면 고객의 개발도 멈출 수 있으므로, 얼마나 빨리 문제를 해결해 주는지는 연동 기능 자체와 함께 구매 판단에 들어간다.

가이거는 인공지능 에이전트가 API를 직접 사용하는 경우에도 주목했다. 그는 두 제품을 에이전트와 연결하는 작업을 성장 실험으로 소개했으며, SocialKit은 에이전트가 외부 도구를 호출하는 연결 규격인 MCP와 사용법을 제공하는 스킬을 지원한다. 같은 데이터 수집 기능을 사람이 작성한 프로그램과 에이전트가 함께 이용할 수 있도록 접근 경로를 늘린 것이다.

그는 자기 X 계정으로 이런 사용 방식을 직접 시험했다. 에이전트가 Claude로 하루 다섯 개의 게시물을 작성하고, 미국의 시간대에 맞춰 일정을 나누면 PostPeer가 예약과 게시를 처리하도록 구성했다. 실행 후에는 예정된 내용을 이메일로 받아 보고, 게시 전까지 대시보드에서 수정하거나 취소할 수 있었다. 이 실험에서는 글을 만드는 기능과 계정에 실제로 게시하는 기능이 분리돼 있었고, PostPeer가 후자를 담당했다.

## 매각 이후 남은 제품을 키우다

2026년 7월 공개한 수치는 두 제품의 역할을 보여 준다. SocialKit의 월 반복 매출은 약 2,800달러, PostPeer는 약 2,400달러였고, 일회성 결제가 각각 월평균 약 700달러와 500달러를 보탰다. 합계는 반복 매출 약 5,200달러에 일회성 매출 약 1,200달러를 더한 월 매출 약 6,400달러였다. 그는 그달 직장을 그만두고 제품 개발에 전념했다.

다음 전환점은 2026년 8월의 SocialKit 매각이었다. 매각 당시 가이거가 공개한 월 반복 매출은 3,290달러였고, 크레딧 묶음 판매가 월평균 약 700달러를 추가하고 있었다. Tiny Startups가 소개한 거래 규모는 매각대금 7만 5,000달러와 자문료 1만 달러를 합친 8만 5,000달러였다. 운영 중에 매출을 만들던 API가 다른 사업자에게 양도할 수 있는 자산으로 이어졌다.

SocialKit 매각 이후에도 PostPeer의 구독 사업은 계속됐다. 2026년 9월 24일 기준 공개 매출 대시보드에는 월 반복 매출 4,403달러와 활성 구독 122건이 표시돼 있었다. 두 제품을 함께 운영하던 시기의 매출에서 한 제품을 매각하고, 남은 제품의 반복 매출을 키우는 단계로 넘어간 것이다.

PostPeer는 플랫폼 연동에서 쌓은 경험에도 별도의 가격을 붙였다. 고객 회사의 이름과 로고가 표시되는 계정 연결 앱을 대신 설정하고 플랫폼 심사를 진행하는 대행 서비스가 그 예다. 2026년 9월 판매 구성은 플랫폼당 일회성 설정비 100~600달러에 월 99달러의 유지 지원료를 더하며, 유지 지원에는 최소 3개월 조건을 뒀다. API 호출에 대한 요금 외에 초기 도입과 심사, 이후의 운영 지원까지 수입원으로 확장한 것이다.

가이거의 사례에서 상품의 경계는 고객이 반복해서 부담하는 작업을 따라 정해졌다. 데이터 수집과 게시를 공통 API로 제공하고, 고객별 설정과 심사 대응은 별도 서비스로 판매했다. 여러 고객에게 재사용할 수 있는 기능과 고객마다 추가로 드는 수고를 구분해 가격을 붙인 점이, 작은 개발 사업을 지속 가능한 수익 구조로 만드는 핵심이었다.
